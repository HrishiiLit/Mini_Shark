Engine ID
Algorithm / data structure
Why selected
E1
Producer-consumer queue + bounded buffer
Separates capture from processing and prevents unlimited memory growth.
E2
Layered protocol parser / decoder
Processes each protocol layer and converts bytes into readable fields.
E3
Lexer + expression parser + expression tree
Supports filters such as tcp.port == 443 and combines conditions.

Hash-map flow tracking + counters + TCP state tracking
Groups packets efficiently and detects useful TCP events.

Security, Errors and Testing
Show important permissions, validation and error responses. Explain how you will check the design.
Area
Simple student explanation
Who can access or change important data?
Only authorized users should capture or view packet data. Saved captures should be protected because they may contain sensitive information.
What happens for invalid input or a failed request?
Check interface names, capture settings and filter syntax. Show a simple error message and continue safely when a packet cannot be decoded.
Is copying of large data necessary, and who owns it?
Avoid unnecessary copies of full packets. Store metadata/references where possible. Captured data must be handled by the authorized user or organization.
How will you test the main functions?
Test live capture, protocol decoding, filters, TCP analysis and statistics using controlled traffic and known packets. Also test invalid filters, high traffic and packet drops.
